- **Author or organisation:** Alex Birsan, @alxbrsn
- **Publication date:** 9 February 2021
- **Reference:** [Dependency Confusion](https://medium.com/@alex.birsan/dependency-confusion-4a5d60fec610)
- **Selection metadata:** 2021, rank 1; not score evidence.

## Core Contribution

A build can select an attacker-owned public package when its dependency name was intended to identify an internal package. Birsan turns that collision into a testing workflow: discover internal names in exposed artifacts, publish matching packages, and observe installation callbacks. The reusable addition is systematic discovery and validation across package ecosystems; the number or prominence of affected companies earns no credit.

Its trigger is a mistyped name, not a public/private namespace collision.
- **Closest pre-cutoff equivalent work:** [pip issue 5045](https://github.com/pypa/pip/issues/5045) (February/March 2018) documents index precedence. More decisively, [Red Hat bug 1835736, original description](https://bugzilla.redhat.com/show_bug.cgi?id=1835736) (14 May 2020) explicitly describes registering the absent public name with a higher version to substitute for a private dependency. This is exploitation knowledge, not merely API documentation.
- **Evidence boundary:** The [original article](https://medium.com/@alex.birsan/dependency-confusion-4a5d60fec610) displays 9 February 2021. The archive filename/frontmatter says 2023; that metadata does not move the cutoff. Score only the original name-discovery, package-publication and callback account, excluding later incidents, responses, and popularity.
